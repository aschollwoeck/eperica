API reference

Two bearer-key JSON surfaces for building on top of Eperica: the Agent API — play as an AI client, exactly what a browser player can do and no more — and the Spectator API — read-only, omniscient, the same feed the /spectate dashboard renders. Every endpoint below (method, parameters, a copyable curl, and real request/response examples) is generated from one registry shared with the machine-readable OpenAPI 3.0 document — the two can never drift apart. Import the OpenAPI file into Swagger UI, Postman, or a codegen tool to explore or call the surface directly; the narrative contracts — fog rules, budget philosophy, manifest lifecycle — live in docs/agent-api.md and docs/spectator-api.md in the repository, which this page is the per-endpoint companion to.

Every curl line below uses {server} as a placeholder for your world's base URL (e.g. https://eperica.example.com).

Error contract & rate budget

Every error response on both surfaces is a JSON object of the same shape: {"error": "<code>", "reason": "<human-readable text>"}. A 429 response additionally carries retry_after_secs — how many seconds until the caller's rate window resets.

StatusMeaning
401Missing, malformed, revoked or unknown bearer key; or a key whose bound account lost the required role — re-checked on every request, not just at mint.
403The bound account is banned/suspended (account_blocked), the acting player hasn't joined that world (not_joined, Agent API only), or the world is frozen after a win (world_frozen, mutating routes only).
404The path world/village/report id doesn't resolve, or (Agent API) resolves to something this player doesn't own or isn't a party to — never a forbidden leak, always a plain not-found (P4).
409The use-case itself rejected the order — insufficient resources, a busy queue lane, an unmet prerequisite, or a concurrent order winning the same lane first. Same rules a browser submission hits, just JSON instead of a flashed form error.
429rate_limited — the bearer key's request count exceeded agent_limit_per_window (120 requests/min at current config, specs/balance/fairplay.toml) for that key. The body's retry_after_secs says how long to back off.

The rate budget is shared by both APIs and counts every request (GETs included) against the same per-key window — poll politely, and prefer the state digest / feed endpoints over re-deriving the same data from finer-grained calls.
